= Active IQ Unified Manager의 성능 이벤트에서 워크로드 역할 식별
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Unified Manager는 역할을 사용하여 성능 이벤트에 워크로드가 관여하는 방식을 식별합니다. 역할에는 피해자, 가해자, 공격자가 있습니다. 사용자 정의 워크로드는 피해자, 가해자, 공격자의 역할을 동시에 수행할 수 있습니다.

|===
| 역할 | 설명 


 a| 
피해자
 a| 
클러스터 구성 요소를 과도하게 사용하는 다른 워크로드(bully라고 함)로 인해 성능이 저하된 사용자 정의 워크로드입니다. 사용자 정의 워크로드만 피해자로 식별됩니다. Unified Manager는 이벤트 발생 시 실제 지연 시간이 지연 시간 예측(예상 범위)에서 크게 증가한 지연 시간 편차를 기준으로 피해자 워크로드를 식별합니다.



 a| 
Bully
 a| 
클러스터 구성 요소를 과도하게 사용하여 다른 워크로드(피해자 워크로드)의 성능을 저하시키는 사용자 정의 또는 시스템 정의 워크로드입니다. Unified Manager는 클러스터 구성 요소 사용량의 편차를 기준으로 악성 워크로드를 식별합니다. 즉, 이벤트 발생 시 실제 사용량이 예상 사용량 범위를 크게 벗어난 경우를 악성 워크로드로 간주합니다.



 a| 
Shark
 a| 
이벤트에 관련된 모든 워크로드와 비교하여 클러스터 구성 요소 사용량이 가장 높은 사용자 정의 워크로드입니다. Unified Manager는 이벤트 중 클러스터 구성 요소의 사용량을 기반으로 샤크 워크로드를 식별합니다.

|===
클러스터의 워크로드는 애그리게이트 및 네트워크와 데이터 처리를 위한 CPU 등 많은 클러스터 구성 요소를 공유할 수 있습니다. 볼륨 등 워크로드가 클러스터 구성 요소의 사용량을 늘려 해당 구성 요소가 워크로드 요구 사항을 효율적으로 충족할 수 없게 되면, 해당 구성 요소는 경합 상태에 놓이게 됩니다. 클러스터 구성 요소를 과도하게 사용하는 워크로드는 bully입니다. 이러한 구성 요소를 공유하고 bully의 영향으로 성능이 저하되는 다른 워크로드는 victim입니다. 중복 제거 또는 Snapshot 복사 등 시스템 정의 워크로드의 활동 또한 "`bullying`"으로 이어질 수 있습니다.

Unified Manager는 이벤트를 감지하면 이벤트를 발생시킨 악성 워크로드, 경합 중인 클러스터 구성 요소, 그리고 악성 워크로드의 활동 증가로 인해 성능이 저하된 피해 워크로드를 포함하여 관련된 모든 워크로드와 클러스터 구성 요소를 식별합니다.

[NOTE]
====
Unified Manager가 가해 워크로드를 식별할 수 없는 경우, 피해 워크로드와 관련된 클러스터 구성 요소에 대해서만 경고를 표시합니다.

====
Unified Manager는 가해 워크로드의 피해자인 워크로드를 식별할 뿐만 아니라, 해당 워크로드가 언제 가해 워크로드가 되는지도 식별할 수 있습니다. 워크로드가 스스로에게 가해자가 될 수도 있습니다. 예를 들어, 정책 그룹 제한으로 인해 제한되는 고성능 워크로드는 자신을 포함하여 정책 그룹 내의 모든 워크로드가 제한되게 합니다. 진행 중인 성능 이벤트에서 가해자 또는 피해자인 워크로드는 역할을 변경하거나 더 이상 이벤트에 참여하지 않을 수도 있습니다.
