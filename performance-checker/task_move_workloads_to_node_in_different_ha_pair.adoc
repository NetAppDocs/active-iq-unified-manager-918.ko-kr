= Active IQ Unified Manager에서 다른 HA 쌍의 노드로 워크로드 이동
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Unified Manager를 사용하면 현재 워크로드가 실행 중인 고가용성(HA) 쌍보다 사용 가능한 성능 용량이 더 많은 다른 HA 쌍의 노드에 있는 애그리게이트를 식별할 수 있습니다. 그런 다음 선택한 볼륨을 새 HA 쌍의 애그리게이트로 이동할 수 있습니다.

.시작하기 전에
* 운영자, 애플리케이션 관리자 또는 스토리지 관리자 역할이 있어야 합니다.
* 클러스터는 최소 두 개의 HA 쌍으로 구성되어야 합니다
+
클러스터에 HA 쌍이 하나만 있는 경우 이 복구 프로세스를 사용할 수 없습니다.

* 현재 성능 문제가 발생하고 있는 HA 쌍의 두 노드 이름을 기록해 두어야 합니다.
* 노드가 성능 이벤트를 수신한 날짜와 시간을 기록해 두어야 합니다.
* Unified Manager는 한 달 이상 성능 데이터를 수집 및 분석해야 합니다.


고성능 워크로드를 여유 성능 용량이 더 많은 노드의 애그리게이트로 이동하면 두 노드의 워크로드 모두 더 효율적으로 작동할 수 있습니다. 이 절차는 고성능 워크로드를 다른 HA 쌍에서 여유 성능 용량이 더 많은 노드로 이동할 수 있도록 다음 리소스를 식별하는 데 도움이 됩니다.

* 동일 클러스터 내에서 사용 가능한 성능 용량이 가장 큰 다른 HA 쌍의 노드
* 새 노드에서 사용 가능한 성능 용량이 가장 큰 애그리게이트
* 현재 노드에서 가장 성능이 뛰어난 볼륨


.단계
. 동일 클러스터 내에서 서로 다른 HA 쌍에 속하는 노드를 식별합니다:
+
.. *이벤트 세부 정보* 페이지에서 노드가 속한 클러스터 이름을 클릭합니다.
+
클러스터 세부 정보는 성능/클러스터 랜딩 페이지에 표시됩니다.

.. *요약* 페이지의 *관리되는 오브젝트* 창에서 *노드*를 클릭합니다.
+
이 클러스터의 노드 목록은 성능: 모든 노드 보기에서 확인할 수 있습니다.

.. 현재 성능 문제가 발생하고 있는 HA 쌍과 다른 HA 쌍에 속한 노드의 이름을 기록하십시오.


. 새로운 HA 쌍에서 사용 가능한 성능 용량이 가장 큰 노드를 식별합니다:
+
.. *성능: 모든 노드* 보기에서 *성능 용량 사용량* 열을 클릭하면 사용률이 가장 낮은 노드 순으로 정렬됩니다.
+
이는 워크로드를 이동할 가능성이 있는 노드 목록을 제공합니다.

.. 워크로드를 이동하려는 다른 HA 페어의 노드 이름을 적어 두십시오.


. 새 노드에서 사용 가능한 성능 용량이 가장 큰 애그리게이트를 식별합니다:
+
.. *성능: 모든 노드* 보기에서 해당 노드를 클릭합니다.
+
노드 세부 정보는 성능/노드 탐색기 페이지에 표시됩니다.

.. *보기 및 비교* 메뉴에서 *이 노드의 애그리게이트*를 선택합니다.
+
이 노드의 애그리게이트가 그리드에 표시됩니다.

.. 애그리게이트를 사용량이 가장 적은 순으로 정렬하려면 *사용된 성능 용량* 열을 클릭하십시오.
+
이는 워크로드를 이동할 수 있는 잠재적인 애그리게이트 목록을 제공합니다.

.. 워크로드를 이동할 애그리게이트의 이름을 적어 두세요.


. 이벤트를 수신한 노드에서 성능이 우수한 워크로드를 식별합니다:
+
.. 해당 이벤트의 *Event* 세부 정보 페이지로 돌아가십시오.
.. *영향을 받는 볼륨* 필드에서 첫 번째 노드의 볼륨 수에 대한 링크를 클릭합니다.
+
성능: 모든 볼륨 보기에는 해당 노드의 볼륨 목록이 필터링되어 표시됩니다.

.. *총 용량* 열을 클릭하여 할당된 공간이 가장 큰 순으로 볼륨을 정렬하십시오.
+
이는 이동하려는 잠재적인 볼륨 목록을 제공합니다.

.. 이동하려는 볼륨의 이름과 해당 볼륨이 상주하는 현재 애그리게이트의 이름을 기록해 두십시오.
.. 이 이벤트에 포함된 두 번째 노드에 대해서도 4c 및 4d 단계를 수행하여 해당 노드에서 이동하려는 볼륨을 식별하십시오.


. 새 노드에서 사용 가능한 성능 용량이 가장 큰 것으로 확인된 애그리게이트로 볼륨을 이동하십시오.
+
ONTAP System Manager, OnCommand Workflow Automation, ONTAP 명령 또는 이러한 툴의 조합을 사용하여 이동 작업을 수행할 수 있습니다.



며칠 후, 해당 노드 또는 애그리게이트에서 동일한 유형의 이벤트를 수신하는지 확인할 수 있습니다.
