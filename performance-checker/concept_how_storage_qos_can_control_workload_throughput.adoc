= Active IQ Unified Manager에서 스토리지 QoS로 워크로드 처리량 제어
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
QoS(서비스 품질) 정책 그룹을 생성하여 해당 그룹에 속한 워크로드의 초당 I/O(IOPS) 또는 처리량(MB/s) 제한을 제어할 수 있습니다. 워크로드가 기본 정책 그룹 등 제한이 설정되지 않은 정책 그룹에 있거나 설정된 제한이 요구 사항을 충족하지 못하는 경우, 제한을 늘리거나 워크로드를 원하는 제한이 있는 새 정책 그룹 또는 기존 정책 그룹으로 이동할 수 있습니다.

"`Traditional`" QoS 정책 그룹은 개별 워크로드(예: 단일 볼륨 또는 LUN)에 할당할 수 있습니다. 이 경우 워크로드는 전체 처리량 제한을 사용할 수 있습니다. QoS 정책 그룹은 여러 워크로드에도 할당할 수 있으며, 이 경우 처리량 제한은 워크로드 간에 "`shared`"됩니다. 예를 들어, 세 개의 워크로드에 9,000 IOPS의 QoS 제한이 할당되면 총 IOPS가 9,000 IOPS를 초과하지 않도록 제한됩니다.

"`Adaptive`" QoS 정책 그룹은 개별 워크로드 또는 여러 워크로드에 할당할 수도 있습니다. 그러나 여러 워크로드에 할당된 경우에도 각 워크로드는 다른 워크로드와 처리량 값을 공유하는 대신 전체 처리량 제한을 받습니다. 또한 적응형 QoS 정책은 워크로드별로 볼륨 크기에 따라 처리량 설정을 자동으로 조정하여 볼륨 크기가 변경되더라도 IOPS 대 테라바이트 비율을 유지합니다. 예를 들어 적응형 QoS 정책에서 최대 처리량이 5,000 IOPS/TB로 설정된 경우 10TB 볼륨의 최대 처리량은 50,000 IOPS가 됩니다. 나중에 볼륨 크기가 20TB로 조정되면 적응형 QoS는 최대 처리량을 100,000 IOPS로 조정합니다.

ONTAP 9.5부터는 적응형 QoS 정책을 정의할 때 블록 크기를 포함할 수 있습니다. 이를 통해 워크로드가 매우 큰 블록 크기를 사용하고 궁극적으로 처리량의 상당 부분을 차지하는 경우 정책을 IOPS/TB 임계값에서 MB/s 임계값으로 효과적으로 변환할 수 있습니다.

공유 그룹 QoS 정책의 경우, 정책 그룹 내 모든 워크로드의 IOPS 또는 MB/s가 설정된 제한을 초과하면 정책 그룹은 워크로드 활동을 제한하기 위해 스로틀링을 적용하며, 이로 인해 정책 그룹 내 모든 워크로드의 성능이 저하될 수 있습니다. 정책 그룹 스로틀링으로 인해 동적 성능 이벤트가 발생하면 이벤트 설명에 관련 정책 그룹의 이름이 표시됩니다.

성능: 모든 볼륨 보기에서 영향을 받은 볼륨을 IOPS 및 MB/s 기준으로 정렬하여 이벤트 발생에 영향을 준 가장 높은 사용량을 보이는 워크로드를 확인할 수 있습니다. 성능/볼륨 탐색기 페이지에서는 다른 볼륨 또는 해당 볼륨의 LUN을 선택하여 영향을 받은 워크로드의 IOPS 또는 MBps 처리량 사용량과 비교할 수 있습니다.

노드 리소스를 과도하게 사용하는 워크로드에 더 제한적인 정책 그룹 설정을 할당하면, 정책 그룹이 해당 워크로드의 활동을 제한하여 노드의 리소스 사용량을 줄일 수 있습니다. 하지만 워크로드가 노드 리소스를 더 많이 사용하도록 하려면 정책 그룹 값을 높이면 됩니다.

System Manager, ONTAP 명령 또는 Unified Manager 성능 서비스 수준을 사용하여 정책 그룹을 관리할 수 있으며, 여기에는 다음과 같은 작업이 포함됩니다:

* 정책 그룹 만들기
* 정책 그룹에 워크로드 추가 또는 제거
* 정책 그룹 간 워크로드 이동
* 정책 그룹의 처리량 제한 변경
* 워크로드를 다른 애그리게이트 및/또는 노드로 이동
