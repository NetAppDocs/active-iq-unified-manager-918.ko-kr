= Active IQ Unified Manager에서 HA 테이크오버로 인한 성능 이벤트에 대응
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Unified Manager를 사용하여 고가용성(HA) 쌍에 속한 클러스터 노드의 높은 Data Processing으로 인해 발생한 성능 이벤트를 조사할 수 있습니다. 또한 Unified Manager를 사용하여 노드의 상태를 확인하고 최근 노드에서 감지된 상태 이벤트가 성능 이벤트에 영향을 미쳤는지 확인할 수 있습니다.

.시작하기 전에
* 운영자, 애플리케이션 관리자 또는 스토리지 관리자 역할이 있어야 합니다.
* 새로운, 확인된 또는 폐기된 성능 이벤트가 있어야 합니다.


.단계
. 이벤트에 대한 정보를 보려면 *이벤트 상세 정보* 페이지를 표시하십시오.
. 이벤트와 관련된 워크로드 및 경합 중인 클러스터 구성 요소를 설명하는 *설명*을 읽으십시오.
+
경합 중인 클러스터 구성 요소로 인해 지연 시간에 영향을 받은 피해 볼륨이 하나 있습니다. 파트너 노드에서 모든 워크로드를 인계받은 Data Processing 노드가 경합 중인 클러스터 구성 요소입니다. '경합 중인 구성 요소'에서 Data Processing 아이콘이 빨간색으로 강조 표시되고, 이벤트 발생 당시 Data Processing을 담당했던 노드 이름이 괄호 안에 표시됩니다.

. *설명*에서 볼륨의 이름을 클릭합니다.
+
볼륨 성능 탐색기 페이지가 표시됩니다. 페이지 상단의 이벤트 타임라인에서 변경 이벤트 아이콘(image:../media/opm_change_icon.gif["이벤트 아이콘 변경"])은 Unified Manager가 HA 테이크오버 시작을 감지한 시간을 나타냅니다.

. HA 테이크오버에 대한 변경 이벤트 아이콘 위에 마우스 커서를 올리면 HA 테이크오버에 대한 세부 정보가 마우스 오버 텍스트로 표시됩니다.
+
지연 시간 차트에서 이벤트는 선택된 볼륨이 HA 인계 시점과 거의 동시에 높은 지연 시간으로 인해 성능 임계값을 초과했음을 나타냅니다.

. *확대 보기*를 클릭하면 지연 시간 차트가 새 페이지에 표시됩니다.
. 보기 메뉴에서 *클러스터 구성 요소*를 선택하면 클러스터 구성 요소별 총 지연 시간을 볼 수 있습니다.
. HA 테이크오버 시작을 나타내는 변경 이벤트 아이콘에 마우스 커서를 놓고 Data Processing 지연 시간과 총 지연 시간을 비교하십시오.
+
HA 테이크오버 당시 Data Processing 노드의 워크로드 수요 증가로 인해 Data Processing이 급증했습니다. CPU 사용률 증가로 인해 지연 시간이 늘어나고 해당 이벤트가 발생했습니다.

. 장애가 발생한 노드를 복구한 후 ONTAP System Manager를 사용하여 HA 기브백을 수행하면 파트너 노드의 워크로드가 복구된 노드로 이동합니다.
. HA 반환이 완료된 후, Unified Manager에서 다음 구성 검색(약 15분 후)이 완료되면 *이벤트 관리* 인벤토리 페이지에서 HA 인계로 인해 발생한 이벤트 및 워크로드를 찾으십시오.
+
HA 테이크오버로 인해 발생한 이벤트의 상태가 이제 사용 중지됨으로 표시되며, 이는 이벤트가 해결되었음을 나타냅니다. Data Processing 구성 요소의 지연 시간이 감소하여 전체 지연 시간이 줄어들었습니다. 선택된 볼륨이 현재 Data Processing에 사용 중인 노드에서 이벤트가 해결되었습니다.
