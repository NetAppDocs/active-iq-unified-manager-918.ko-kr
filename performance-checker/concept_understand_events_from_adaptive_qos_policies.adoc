= Active IQ Unified Manager에서 정의된 블록 크기를 사용하는 적응형 QoS 이벤트 이해
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
적응형 QoS 정책 그룹은 볼륨 크기에 따라 처리량 상한 또는 하한을 자동으로 조정하여 볼륨 크기 변화에 따른 IOPS 대 TB 비율을 유지합니다. ONTAP 9.5부터는 QoS 정책에서 블록 크기를 지정하여 MB/s 임계값을 동시에 적용할 수 있습니다.

적응형 QoS 정책에서 IOPS 임계값을 할당하는 것은 각 워크로드에서 발생하는 작업 수에만 제한을 두는 것입니다. 워크로드를 생성하는 클라이언트에 설정된 블록 크기에 따라 일부 IOPS는 훨씬 더 많은 데이터를 포함하므로 작업을 처리하는 노드에 훨씬 더 큰 부담을 줍니다.

워크로드의 MB/s 값은 다음 공식을 사용하여 생성됩니다:

[listing]
----
MB/s = (IOPS * Block Size) / 1000
----
워크로드의 평균 IOPS가 3,000이고 클라이언트의 블록 크기가 32KB로 설정된 경우, 이 워크로드의 유효 MB/s는 96입니다. 동일한 워크로드의 평균 IOPS가 3,000이고 클라이언트의 블록 크기가 48KB로 설정된 경우, 이 워크로드의 유효 MB/s는 144입니다. 블록 크기가 더 클 때 노드가 50% 더 많은 데이터를 처리하는 것을 확인할 수 있습니다.

다음은 블록 크기가 정의된 적응형 QoS 정책과 클라이언트에 설정된 블록 크기에 따라 이벤트가 트리거되는 방식을 살펴보겠습니다.

정책을 생성하고 최대 처리량을 2,500 IOPS/TB, 블록 크기를 32KB로 설정합니다. 이렇게 하면 사용 용량이 1TB인 볼륨의 경우 MB/s 임계값이 80MB/s((2500 IOPS * 32KB) / 1000)로 효과적으로 설정됩니다. 참고로 Unified Manager는 처리량 값이 정의된 임계값보다 10% 낮을 경우 경고 이벤트를 생성합니다. 이벤트는 다음과 같은 상황에서 생성됩니다:

|===
| 사용된 용량 2+| 처리량이 이 수치를 초과하면 이벤트가 발생합니다... 


|  | IOPS | MB/s 


 a| 
1 TB
 a| 
2,250 IOPS
 a| 
72 MB/s



 a| 
2 TB
 a| 
4,500 IOPS
 a| 
144 MB/s



 a| 
5 TB
 a| 
11,250 IOPS
 a| 
360 MB/s

|===
볼륨이 사용 가능한 공간의 2TB를 사용하고 있고, IOPS가 4,000이며, 클라이언트에서 QoS 블록 크기가 32KB로 설정된 경우, MB/ps 처리량은 128MB/s((4,000 IOPS * 32KB) / 1000)입니다. 이 시나리오에서는 4,000 IOPS와 128MB/s 모두 2TB 공간을 사용하는 볼륨에 대한 임계값 미만이므로 이벤트가 생성되지 않습니다.

만약 볼륨이 사용 가능한 공간 중 2TB를 사용하고 있고, IOPS가 4,000이며, 클라이언트에서 QoS 블록 크기가 64KB로 설정되어 있다면, MB/s 처리량은 256 MB/s((4,000 IOPS * 64 KB) / 1000)입니다. 이 경우 4,000 IOPS는 이벤트를 발생시키지 않지만, MB/s 값인 256 MB/s는 임계값인 144 MB/s를 초과하므로 이벤트가 발생합니다.

따라서 블록 크기를 포함하는 적응형 QoS 정책에 대해 MB/s 위반으로 이벤트가 발생하면 이벤트 세부 정보 페이지의 시스템 진단 섹션에 MB/s 차트가 표시됩니다. 적응형 QoS 정책에 대해 IOPS 위반으로 이벤트가 발생하면 시스템 진단 섹션에 IOPS 차트가 표시됩니다. IOPS와 MB/s 모두에서 위반이 발생하면 두 개의 이벤트가 수신됩니다.

QoS 설정 조정에 대한 자세한 내용은  https://docs.netapp.com/us-en/ontap/performance-admin/index.html["성능 관리 개요"]을(를) 참조하십시오.
