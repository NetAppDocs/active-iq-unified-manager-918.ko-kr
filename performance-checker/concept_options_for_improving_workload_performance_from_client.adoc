= Active IQ Unified Manager에서 클라이언트측 설정을 조정하여 워크로드 성능을 향상시킵니다
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
성능 이벤트와 관련된 볼륨에 I/O를 전송하는 애플리케이션이나 데이터베이스 등 클라이언트 워크로드를 확인하여 클라이언트 측 변경으로 이벤트를 해결할 수 있는지 판단할 수 있습니다.

클러스터의 볼륨에 연결된 클라이언트의 I/O 요청량이 증가하면 클러스터는 수요를 충족하기 위해 더 많은 작업을 수행해야 합니다. 클러스터의 특정 볼륨에 대해 I/O 요청량이 많은 클라이언트를 알고 있다면 해당 볼륨에 액세스하는 클라이언트 수를 조정하거나 해당 볼륨에 대한 I/O 양을 줄여 클러스터 성능을 향상시킬 수 있습니다. 또한 해당 볼륨이 속한 QoS 정책 그룹에 제한을 적용하거나 제한을 늘릴 수도 있습니다.

클라이언트와 해당 애플리케이션을 조사하여 클라이언트가 평소보다 많은 I/O를 전송하는지 여부를 확인할 수 있습니다. 이로 인해 클러스터 구성 요소에서 경합이 발생할 수 있습니다. 이벤트 세부 정보 페이지의 시스템 진단 섹션에는 경합이 발생한 구성 요소를 사용하는 상위 볼륨 워크로드가 표시됩니다. 특정 볼륨에 액세스하는 클라이언트를 알고 있다면 해당 클라이언트로 이동하여 클라이언트 하드웨어 또는 애플리케이션이 예상대로 작동하지 않거나 평소보다 많은 작업을 수행하는지 확인할 수 있습니다.

MetroCluster 구성에서 로컬 클러스터의 볼륨에 대한 쓰기 요청은 원격 클러스터의 볼륨에 미러링됩니다. 로컬 클러스터의 소스 볼륨을 원격 클러스터의 대상 볼륨과 동기화 상태로 유지하면 MetroCluster 구성에서 두 클러스터의 요구가 증가할 수 있습니다. 이러한 미러링된 볼륨에 대한 쓰기 요청을 줄이면 클러스터의 동기화 작업 횟수가 줄어들어 다른 워크로드에 대한 성능 영향이 감소합니다.
