:allow-uri-read:

[role="lead"]
성능/노드 장애 조치 계획 페이지의 구성 요소는 그리드와 비교 창에 표시됩니다. 이러한 섹션을 통해 노드 장애 조치가 인수 노드의 성능에 미치는 영향을 평가할 수 있습니다.



[[performance-statistics-grid]]
== 성능 통계 표

성능/노드 장애 조치 계획 페이지에는 지연 시간, IOPS, 사용률 및 사용된 성능 용량에 대한 통계가 포함된 표가 표시됩니다.

[NOTE]
====
이 페이지와 성능/노드 성능 탐색기 페이지에 표시되는 지연 시간 및 IOPS 값이 일치하지 않을 수 있습니다. 이는 노드 장애 조치를 예측하기 위해 서로 다른 성능 카운터를 사용하여 값을 계산하기 때문입니다.

====
그리드에서 각 노드에는 다음 역할 중 하나가 할당됩니다:

* 프라이머리
+
HA 파트너에 장애가 발생할 경우 해당 파트너의 기능을 인계받는 노드입니다. 루트 오브젝트는 항상 기본 노드입니다.

* 파트너
+
장애 조치 시나리오에서 장애가 발생하는 노드.

* 예상 테이크오버
+
기본 노드와 동일합니다. 이 노드에 표시되는 성능 통계는 장애가 발생한 파트너를 인계받은 후 테이크오버 노드의 성능을 보여줍니다.



[NOTE]
====
장애 조치 후 인수 노드의 워크로드는 두 노드의 워크로드를 합친 것과 동일하지만, 예상 인수 노드의 통계는 기본 노드와 파트너 노드의 통계 합계가 아닙니다. 예를 들어 기본 노드의 지연 시간이 2ms/op이고 파트너 노드의 지연 시간이 3ms/op인 경우 예상 인수 노드의 지연 시간은 4ms/op가 될 수 있습니다. 이 값은 Unified Manager가 수행하는 계산입니다.

====
파트너 노드가 루트 오브젝트가 되도록 하려면 해당 파트너 노드의 이름을 클릭할 수 있습니다. 성능/노드 성능 탐색기 페이지가 표시되면 *장애 조치 계획* 탭을 클릭하여 이 노드 장애 시나리오에서 성능이 어떻게 변하는지 확인할 수 있습니다. 예를 들어 Node1이 기본 노드이고 Node2가 파트너 노드인 경우 Node2를 클릭하여 기본 노드로 설정할 수 있습니다. 이렇게 하면 어떤 노드에 장애가 발생하는지에 따라 예상 성능이 어떻게 변하는지 확인할 수 있습니다.



[[comparing-pane]]
== 비교 패널

다음 목록은 비교 창에 기본적으로 표시되는 구성 요소를 설명합니다:

* *이벤트 차트*
+
이 정보는 성능/노드 성능 탐색기 페이지에 표시되는 것과 동일한 형식으로 표시됩니다. 이 정보는 기본 노드에만 해당됩니다.

* *카운터 차트*
+
이 차트들은 그리드에 표시된 성능 카운터에 대한 과거 통계를 보여줍니다. 각 차트에서 Estimated Takeover 노드 그래프는 특정 시점에 장애 조치가 발생했을 경우 예상되는 성능을 나타냅니다.

+
예를 들어, 2월 8일 오전 11시에 예상 테이크오버 노드의 사용률 차트가 73%로 표시된다고 가정해 보겠습니다. 그 시간에 페일오버가 발생했다면 테이크오버 노드의 사용률은 73%였을 것입니다.

+
과거 통계 자료를 활용하면 장애 조치 시작에 가장 적합한 시점을 파악하여, 인수 노드의 과부하 가능성을 최소화할 수 있습니다. 인수 노드의 예상 성능이 허용 가능한 수준일 때만 장애 조치를 예약할 수 있습니다.



기본적으로 루트 오브젝트와 파트너 노드 모두에 대한 통계가 비교 창에 표시됩니다. 성능/노드 성능 탐색기 페이지와 달리 이 페이지에는 통계 비교를 위해 오브젝트를 추가할 수 있는 *추가* 버튼이 표시되지 않습니다.

성능/노드 성능 탐색기 페이지에서와 마찬가지로 비교 창을 사용자 지정할 수 있습니다. 다음은 차트 사용자 지정 예시입니다.

* 카운터 차트에서 노드의 통계를 표시하거나 숨기려면 노드 이름을 클릭하십시오.
* *확대 보기*를 클릭하면 특정 카운터에 대한 자세한 차트를 새 창에서 볼 수 있습니다.
