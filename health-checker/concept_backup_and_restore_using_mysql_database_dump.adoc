= Active IQ Unified Manager에서 MySQL 데이터베이스 덤프를 사용하여 백업 및 복원
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
MySQL 데이터베이스 덤프 백업은 시스템 장애 또는 데이터 손실 발생 시 사용할 수 있는 Active IQ Unified Manager 데이터베이스 및 구성 파일의 복사본입니다. 백업이 로컬 대상 또는 원격 대상에 기록되도록 예약할 수 있습니다. Active IQ Unified Manager 호스트 시스템 외부에 있는 원격 위치를 지정하는 것을 강력히 권장합니다.

[NOTE]
====
Unified Manager가 Linux 및 Windows 서버에 설치된 경우 MySQL 데이터베이스 덤프가 기본 백업 메커니즘입니다. 하지만 Unified Manager가 대규모 클러스터 및 노드를 관리하거나 MySQL 백업 완료에 오랜 시간이 걸리는 경우 Snapshot 복사본을 사용하여 백업할 수 있습니다. 이 기능은 Red Hat Enterprise Linux 및 Windows에서 사용할 수 있습니다.

====
데이터베이스 덤프 백업은 백업 디렉터리에 있는 단일 파일과 데이터베이스 저장소 디렉터리에 있는 하나 이상의 파일로 구성됩니다. 백업 디렉터리의 파일은 백업을 다시 생성하는 데 필요한 데이터베이스 저장소 디렉터리의 파일에 대한 포인터만 포함하고 있으므로 크기가 매우 작습니다.

데이터베이스 백업을 처음 생성하면 백업 디렉터리에 단일 파일이 생성되고 데이터베이스 저장소 디렉터리에 전체 백업 파일이 생성됩니다. 다음 백업을 생성하면 백업 디렉터리에 단일 파일이 생성되고 전체 백업 파일과의 차이점을 포함하는 증분 백업 파일이 데이터베이스 저장소 디렉터리에 생성됩니다. 이 과정은 다음 그림과 같이 최대 보존 설정값에 도달할 때까지 추가 백업을 생성할 때마다 계속됩니다.

image::../media/database_backup.gif[데이터베이스 저장소의 전체 백업 파일과 증분 백업 파일을 가리키는 세 개의 백업 디렉터리 파일을 보여주는 다이어그램]

[NOTE]
====
이 두 디렉터리에 있는 백업 파일의 이름을 바꾸거나 삭제하지 마십시오. 그렇지 않으면 이후 복원 작업이 실패합니다.

====
백업 파일을 로컬 시스템에 저장하는 경우, 시스템 문제 발생 시 전체 복원이 필요할 때 백업 파일을 사용할 수 있도록 원격 위치로 복사하는 프로세스를 시작해야 합니다.

백업 작업을 시작하기 전에 Active IQ Unified Manager는 무결성 검사를 수행하여 필요한 모든 백업 파일과 백업 디렉터리가 존재하고 쓰기 가능한지 확인합니다. 또한 시스템에 백업 파일을 생성할 충분한 공간이 있는지도 확인합니다.
