= Active IQ Unified Manager API를 사용하여 CIFS를 지원하도록 NFS 파일 공유 수정
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
NFS 파일 공유를 수정하여 CIFS 프로토콜을 지원할 수 있습니다. 파일 공유 생성 시 동일한 파일 공유에 대해 액세스 제어 목록(ACL) 매개변수와 내보내기 정책 규칙을 모두 지정할 수 있습니다. 그러나 NFS 파일 공유를 생성한 동일한 볼륨에서 CIFS를 활성화하려는 경우, 해당 파일 공유의 ACL 매개변수를 업데이트하여 CIFS를 지원할 수 있습니다.

.시작하기 전에
. NFS 파일 공유는 내보내기 정책 세부 정보만으로 생성되어 있어야 합니다. 자세한 내용은 _파일 공유 관리_ 및 _스토리지 워크로드 수정_을 참조하십시오.
. 이 작업을 실행하려면 파일 공유 키가 있어야 합니다. 파일 공유 세부 정보를 보고 작업 ID를 사용하여 파일 공유 키를 가져오는 방법에 대한 자세한 내용은 _CIFS 및 NFS 파일 공유 프로비저닝_을 참조하십시오.


이는 ACL 매개변수를 추가하지 않고 내보내기 정책 규칙만 추가하여 생성한 NFS 파일 공유에 적용됩니다. ACL 매개변수를 포함하도록 NFS 파일 공유를 수정합니다.

.단계
. NFS 파일 공유에서 CIFS 액세스를 허용하기 위한 ACL 세부 정보를 사용하여  `PATCH` 작업을 수행합니다.
+
[cols="3*"]
|===
| 범주 | HTTP 동사 | 경로 


 a| 
storage-provider
 a| 
PATCH
 a| 
`/storage-provider/file-shares`

|===
+
*샘플 cURL*

+
다음 예시와 같이 사용자 그룹에 할당한 액세스 권한에 따라 ACL이 생성되어 파일 공유에 할당됩니다.

+
[listing]
----
{
  "access_control": {
    "acl": [
      {
        "permission": "read",
        "user_or_group": "everyone"
      }
    ],
    "active_directory_mapping": {
      "key": "3b648c1b-d965-03b7-20da-61b791a6263c"
    }
----
+
*샘플 JSON 출력*

+
이 작업은 업데이트를 실행하는 작업의 작업 ID를 반환합니다.

. 매개변수가 올바르게 추가되었는지 확인하려면 동일한 파일 공유에 대한 파일 공유 세부 정보를 조회하십시오.
+
[cols="3*"]
|===
| 범주 | HTTP 동사 | 경로 


 a| 
storage-provider
 a| 
GET
 a| 
`/storage-provider/file-shares/\{key}`

|===
